# 开发预算v1：先保精度，再证明在线节省

日期：2026-11-27。依据本轮[三模型实测参照](外部对比表.md)，不是引用论文速度，也不使用前轮不同计时边界的数字。本轮没有启动任何微调或重训。

T05在相同协议下是当前应保住的域内基线；两个外部模型为零样本迁移，低成绩不构成放宽精度门槛的理由。

| 项目 | 不退化验收线 | 下一阶段开发目标 |
|---|---:|---:|
| SR@3px | ≥332/952（34.8739%） | 保持该底线 |
| SR@5px | ≥520/952（54.6218%） | 保持该底线；提高精度另行报告 |
| 完整端到端中位延迟 | ≤10.138ms | **≤8.111ms**；72个影像×轮配对中位延迟比的中位数≤0.80 |
| 完整端到端P95 | ≤13.397ms | ≤13.397ms，不能只优化中位数而恶化长尾 |
| 推理峰值allocated显存 | ≤53.905MiB | **≤43.124MiB** |

延迟和显存目标是实测T05的80%，即明确的20%下降工程目标；不是本轮已经达到的结果，也不是由三种方法统计确定的全局最优预算。T05三轮中位标准差约2.66%，20%的目标意在避免把约1%的微小变化当作足够收益，仍必须做配对复测。

验收继续使用原952对固定验证与同一独立探针/RANSAC/失败分母；RMSE中位与P90、求解失败、配准失败、双向成败变化同时列出，不能仅靠恰好越过阈值的少数样本宣称机制有效。不能用测试集改结构、阈值或预算。

时延复核沿用同24对、RTX5090单卡、batch1、3轮；相同CPU原图到最终仿射边界，含预处理/H2D/匹配/采样/过滤/D2H/RANSAC，禁止feature cache与hook。建议候选和T05在相同轮中交替/轮换，每个影像×轮先取重复中位延迟，再计算候选/T05比值。72个比值的中位数须≤0.80，且三轮各自比值中位数均<1；不能与旧GPU驻留输入计时混用，也不能只挑最快轮。显存各用独立新进程，取24对最大allocated，保留自己的库工作区；不报告为含驱动context的物理总显存。

约8.11ms与43.12MiB是**开发目标**，不是任一当前稀疏精化配置已通过的验收结果。前轮global_conf128虽保持精度，但其选择开销抵消网络收益；本轮也没有为它改变代码或追加训练。优先验证编码/相关/候选操作中有依据的成本减少，再决定是否值得训练评分器或重构模块。

外部模型未来若更换权重、分辨率、精度或引入SAR微调，应单独列协议与版本；不能用当前零样本结果背书同域最优。机器可读预算见[development_budget.json](development_budget.json)。
